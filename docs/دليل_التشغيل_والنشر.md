# دليل تشغيل ونشر Forex Scanner

هذا الدليل موجه لصاحب المشروع. الحزمة لا تتضمن ملف `.env` ولا مفاتيح حقيقية؛ أنشئ ملفك الخاص على الخادم ولا ترسله في المحادثات.

## 1. المتطلبات

- Python 3.12 موصى به (تم الاختبار على Python 3.12.3).
- اتصال إنترنت صادر إلى Yahoo Finance وتقويم الأخبار وTelegram.
- بوت Telegram أنشأته عبر BotFather، وحساب المالك الرقمي.
- عند استخدام TradingView: عنوان HTTPS عام يصل إلى الخادم، وخطة TradingView تسمح بتنبيهات Webhook. لا يُعد وجود الكود وحده إثباتاً لصلاحية حسابك أو وصوله من الإنترنت.
- تخزين دائم على الخادم لحفظ قاعدة SQLite وقائمة المتابعة وسجل النتائج بين عمليات النشر.

## 2. تجهيز الملفات لأول مرة

1. فك ضغط `Forex_final.zip` إلى مجلد على الخادم.
2. افتح الطرفية داخل المجلد وأنشئ بيئة Python:

   ```bash
   python3.12 -m venv .venv
   . .venv/bin/activate
   python -m pip install --upgrade pip
   pip install -r requirements.txt
   ```

3. انسخ ملف الإعداد النموذجي وأنشئ إعدادات خاصة بالخادم:

   ```bash
   cp .env.example .env
   ```

4. افتح `.env` بمحرر نصوص، وأدخل القيم التالية:

   - `TELEGRAM_BOT_TOKEN`: رمز البوت من BotFather.
   - `TELEGRAM_ALLOWED_USER_ID`: رقم حساب Telegram الخاص بك، أرقام فقط؛ لا تستخدم اسم المستخدم. البوت يرفض الأوامر إذا تُرك هذا الحقل فارغاً.
   - `TELEGRAM_CHAT_ID`: المحادثة الافتراضية، أو رقم المجموعة إذا أردت استخدام لوحة الأوامر من تلك المجموعة. أوامر المجموعة تتطلب مطابقة هذا الرقم.
   - `TELEGRAM_CHANNEL_ID`: معرف قناة التوصيات التي تريد النشر فيها، مثل `@اسم_القناة` أو المعرّف الرقمي. أضف البوت إلى القناة بصلاحية النشر. لا ينشئ المشروع قناة جديدة ولا يغير الوجهة تلقائياً.
   - `WEBHOOK_SHARED_SECRET`: سلسلة عشوائية طويلة وفريدة (32 محرفاً أو أكثر). قيمة المثال غير مقبولة للتشغيل العام.

5. اترك `ENABLE_PAPER_TRADING=false` ما لم ترد، بشكل منفصل، استخدام OANDA Practice فقط. لا يوجد تنفيذ تداول بأموال حقيقية في هذه الحزمة.

## 3. البيانات والأخبار

مصدر OHLCV المنفذ حالياً هو Yahoo Finance عبر `yfinance`، وهو تاريخي/قد يكون متأخراً ولا يثبت تغذية أسعار لحظية. لذلك ترفض بوابة النشر الحالية إرسال توصيات جديدة حتى يُضاف مزود لحظي موثق ومختبر؛ لا تفعّل تجاوزاً يدوياً لهذا الحاجز. `DATA_PROVIDER` لا يضيف مزوداً بمجرد تغيير اسمه. يُحوّل الذهب `XAUUSD` إلى عقد الذهب الآجل `GC=F` كبديل سعري؛ هذا ليس سعر XAUUSD الفوري ولا بيانات Bid/Ask، وقد تختلف الأسعار والجلسات عن وسيطك.

اترك `ENABLE_NEWS_FILTER=true`. عند تعذر التحقق من التقويم أو قدم بياناته، يوقف النظام نشر التوصيات احترازياً. يستطيع الخادم إرسال إشعار خاص للأدمن عند تعطل مصدر الأخبار أو بيانات السوق وعند عودتهما.

على Railway أو أي استضافة مشابهة، أنشئ Volume مستمراً (مثلاً `/data`) واضبط:

```env
FOREX_DATA_DIR=/data
```

اضبط المنصة لتمرير منفذ `PORT` إلى التطبيق. ضع TLS/HTTPS في نقطة الدخول العامة؛ لا تعرض منفذ Webhook HTTP عارياً على الإنترنت. النسخ المستمر مهم حتى لا تضيع التوصيات المفتوحة وسجل النتائج بعد إعادة التشغيل.

## 4. تشغيل البوت

من مجلد المشروع ومع تفعيل البيئة الافتراضية:

```bash
python main.py
```

افتح محادثة البوت الخاصة واضغط Start أو أرسل `/start`. لا تعمل الأوامر إلا للحساب الذي يطابق `TELEGRAM_ALLOWED_USER_ID`. تشمل الوظائف الأساسية `/scan` و`/watchlist` و`/add` و`/remove`، مع أوامر التقييم والموافقة الموضحة في README. تتطلب مجموعة Telegram أيضاً ضبط `TELEGRAM_CHAT_ID` على رقم المجموعة.

اضبط `TELEGRAM_CHANNEL_ID` صراحةً على قناة الإشارات؛ لا يستخدم البوت `TELEGRAM_CHAT_ID` أو الخاص كبديل. ردود `/scan` و`/scan_all` لا ينبغي أن تعرض مستويات توصية إذا رفضت البوابة النشر. حالياً لا تُنشر توصيات جديدة لأن مصدر الأسعار المتاح غير مثبت اللحظية. رسائل `/results` نواتج سعرية تقديرية من شموع OHLCV وليست صفقات منفذة أو أرباحاً محققة لدى وسيط. تنبيهات تعذر تقويم الأخبار تذهب للأدمن على الخاص، ولا يُدّعى وجود خبر فعلي عندما يكون المصدر غير متاح.

### إذا كانت الأوامر لا تستجيب

جرّب هذه الخطوات بالترتيب، وكل خطوة لا تحتاج برمجة:

1. أرسل `/id` للبوت. هذا الأمر يعمل لأي شخص ويرد برقم حسابك. إذا لم يرد البوت على `/id` إطلاقاً فالخدمة متوقفة أو التوكن خاطئ: افتح سجلات Railway وابحث عن `Telegram bot could not start` أو `Telegram rejected TELEGRAM_BOT_TOKEN`.
2. إذا رد البوت برسالة "غير مخوّل" فهو يعمل لكن الرقم المضبوط خاطئ. انسخ الرقم الظاهر في الرد وضعه في `TELEGRAM_ALLOWED_USER_ID` ثم أعد تشغيل الخدمة.
3. إذا كانت الردود عشوائية أو تختفي، فغالباً توجد نسخة ثانية تعمل بنفس التوكن (جهازك المحلي أو خدمة Railway قديمة). سيرسل البوت لك رسالة "تعارض في البوت" ويكتب `Telegram polling conflict` في السجل. أوقف النسخة الأخرى.
4. بعد كل تشغيل ناجح يرسل البوت لك رسالة خاصة "تم تشغيل بوت TONPO Signals" مع نتيجة فحص صلاحيات القناة.

ما تم إصلاحه في الكود: كان البوت يعالج رسالة واحدة في كل مرة، فإذا ضغطت "فحص شامل" أو "تطوير الاستراتيجية" يتوقف الرد على `/start` وباقي الأزرار حتى ينتهي الفحص (قد يستغرق دقائق). الآن يعالج البوت حتى 8 رسائل معاً، وأي فشل في تشغيل Telegram لا يوقف الخدمة كلها بل يعاد المحاولة تلقائياً.

### عرض نتائج كل صفقة

- اضغط زر "📈 نتائج الصفقات" أو أرسل `/results`: ملخص نتائج سعرية تقديرية مشتقة من OHLCV (رابحة/خاسرة/ملتبسة/مفتوحة ومجموع R) ثم قائمة بكل السجلات. هذه النسبة ليست سجلاً لصفقات منفذة أو أرباح وسيط فعلية، ولا تشمل Bid/Ask أو السبريد والانزلاق والعمولات. لا تُحذف ولا تُخفى أي خسارة مسجلة.
- اضغط على رقم أي صفقة أو أرسل `/trade 1a2b3c4d` لترى تفاصيلها كاملة: الدخول والوقف والهدف وسعر الخروج والمدة والنقاط وR، مع صورة الشارت الأصلية.
- عند تحقق الهدف أو الوقف تُنشر رسالة النتيجة في القناة نفسها كرد على منشور التوصية الأصلي، فتبقى كل صفقة ونتيجتها مرتبطتين.
- تتم متابعة الصفقات المفتوحة كل 5 دقائق (`OUTCOME_CHECK_INTERVAL_SECONDS`) وحتى أثناء توقف النشر بسبب الأخبار.

### فحوص النشر الجديدة

قبل نشر أي توصية، من أي مسار (الفحص التلقائي، `/scan_all`، زر النشر، أو TradingView)، يتحقق النظام من:

| الفحص | ماذا يفعل | الإعداد |
|---|---|---|
| مصدر الأسعار | يرفض نشر توصيات جديدة حتى يُضاف مزود لحظي موثق مع ختم وقت قابل للتحقق. `yfinance` الحالي تاريخي/قد يتأخر، لذلك لا يكفي حداثة الشمعة لإثبات real-time | لا يوجد مزود لحظي مفعّل حالياً |
| الأخبار | يوقف نشر الرمز إذا كان خبر قوي يخص عملاته (الذهب يتأثر بأخبار الدولار). إذا تعذر جلب التقويم يُرفض النشر احترازياً | `ENABLE_NEWS_FILTER` |
| ساعات السوق | يوقف نشر إشارات FX والمعادن أثناء إغلاق عطلة نهاية الأسبوع. الحاجز إلزامي ولا يتجاوزه الإعداد القديم حتى إن كان false؛ لا يغطي بالضرورة عطل الوسيط الخاصة بكل أصل | `ENABLE_MARKET_HOURS_FILTER` (متوافقية قديمة، لا يتجاوز الحاجز) |
| الإطار الأعلى | يرفض الصفقة إذا كان الإطار الأعلى (مثلاً 4 ساعات لصفقة الساعة) في اتجاه قوي معاكس، أو هيكله معاكس والسعر في الجهة الخاطئة من EMA50 | `ENABLE_MTF_FILTER` |
| الدولار للذهب | يرفض شراء الذهب إذا ارتفع مؤشر الدولار DXY أكثر من 0.35% خلال 24 ساعة (والعكس للبيع). إذا تعذر جلب DXY يُتجاهل هذا الفحص فقط | `ENABLE_DXY_FILTER` |

عند الرفض يظهر السبب لك في رد `/scan_all` أو زر النشر، وفي سجل الخدمة.

## 5. إعداد TradingView

**قيد مهم في النسخة الحالية:** endpoint لا يعامل تنبيه TradingView كسعر السوق الوحيد؛ بل يعيد جلب OHLCV عبر `yfinance` ويطلب أن يؤكد الماسح الداخلي الاتجاه والسعر. كما أن بوابة النشر الحالية تحظر Yahoo لأنه غير موثق كمصدر لحظي. لذلك إعداد التنبيه وحده لن ينشر توصية حالياً؛ يلزم أولاً إضافة مزود لحظي موثق أو تعديل معماري يختبر حزمة TradingView اللحظية بأمان. endpoint ينتظر الفحص الداخلي قبل الرد، وقد يتجاوز مهلة TradingView البالغة 3 ثوانٍ إذا تأخر مصدر البيانات؛ يلزم اختبار ذلك أو إضافة إقرار سريع وطابور معالجة قبل تشغيله إنتاجياً.

بعد توافر مصدر صالح وسرّ آمن، اتبع الخطوات:

1. انشر commit المطلوب إلى خدمة عامة عبر HTTPS، وتأكد من `/health`. استخدم مسار webhook الكامل:

   ```text
   https://YOUR_PUBLIC_HOST/webhook/tradingview
   ```

   يجب أن يكون النطاق عاماً وشهادة HTTPS صالحة. لا تستخدم `localhost` أو عنواناً داخلياً أو منفذ Uvicorn غير المدعوم من TradingView.

2. في Railway اضبط `WEBHOOK_SHARED_SECRET` كسلسلة عشوائية فريدة لا تقل عن 32 محرفاً. لا تستخدم القيمة الافتراضية أو placeholder. السر مطلوب داخل رسالة TradingView؛ استخدمه لهذا التكامل فقط ولا تضع فيه كلمة مرور أو مفتاح وسيط. أدخله في خانة `Webhook Shared Secret` بإعدادات المؤشر، وأنشئ Alert جديداً بعد تغيير القيمة حتى تُحفظ مدخلات التنبيه الجديدة.

3. افتح في TradingView رمزاً وفريماً من مصدر البيانات الذي تريد مراقبته، ثم أضف `pine_script/tv_indicator.pine` إلى الرسم من Pine Editor. الفريمات التي يقبلها الخادم هي `15m` و`30m` و`1h` و`4h` و`1d`، ويقبل أيضاً صيغ TradingView `15` و`30` و`60` و`240` و`D`. المؤشر مبرمج كتقريب لشروط المشروع وليس استراتيجية تداول مضمونة أو أمراً ينفذه وسيط.

4. أنشئ Alert جديداً، واختر شرط المؤشر **Forex Scanner Bridge → Any alert() function call**. فعّل **Webhook URL** في تبويب Notifications، ثم ضع عنوان endpoint أعلاه. `alert()` يرسل JSON المولد من Pine Script؛ لا تختَر `alertcondition()` إذا كنت تتوقع JSON الكامل، لأن رسائله المضمنة نصوص موجزة فقط.

5. حمولة Pine الحالية ترسل `ticker` و`timeframe` و`bar_time` و`signal` و`price` و`secret` واسم الاستراتيجية. لا ترسل حالياً `stop_loss` أو `take_profit`؛ لذلك يحسب Python وقفاً افتراضياً (20 pip لأزواج FX) وأهدافاً مبنية على نسبة المخاطرة، وليس مستويات وقف/هدف مستقلة من TradingView. لا تعتبرها أوامر منفذة لدى وسيط.

6. فعّل التحقق الثنائي (2FA) في حساب TradingView؛ المنصة تشترطه لإرسال Webhooks. تسمح TradingView بمنافذ 80 و443 فقط، وقد تلغي الطلب إذا لم يرد الخادم خلال 3 ثوانٍ، وتعرض نجاح/فشل التسليم في **Webhook status** بسجل التنبيه. كما تنبه المنصة إلى أن التسليم قد يفشل أحياناً؛ راقب Alert log وسجلات الخدمة معاً. [إرشادات TradingView الرسمية](https://www.tradingview.com/support/solutions/43000529348-how-to-configure-webhook-alerts/) و[دليل Pine Script للتنبيهات](https://www.tradingview.com/pine-script-docs/concepts/alerts/).

7. بعد اختبار آمن، راقب استجابة endpoint: `not_corroborated` تعني أن الماسح الداخلي لم يوافق، و`blocked_by_filters` تعني أن بوابة المشروع رفضت الإرسال، و`market_data_unavailable` تعني تعذر جلب بيانات داخلية. `GET /health` يثبت جاهزية HTTP فقط، لا وصول تنبيه أو نشر توصية. خيارا `WEBHOOK_ENFORCE_TV_IPS=true` و`TRADINGVIEW_HEARTBEAT_MINUTES` اختياريان؛ لا تفعّل حصر IP خلف proxy حتى تتأكد أن التطبيق يرى عنوان TradingView الحقيقي.

## 6. تقارير مراجعة النتائج الاختيارية

التقارير معطلة افتراضياً. لتفعيل تقرير دوري خاص بالأدمن:

```env
AI_REVIEW_ENABLED=true
AI_REPORT_INTERVAL_HOURS=24
```

بدون مفاتيح مزود خارجي ينتج النظام إحصاءات محلية من التوصيات المغلقة فقط. ولا يغير أي استراتيجية. لإضافة مراجعة نموذج اختياري متوافق مع واجهة OpenAI Chat Completions، اضبط أيضاً `AI_API_BASE_URL` على عنوان HTTPS، و`AI_API_KEY` و`AI_MODEL`. لا تُرسل بيانات إلى النموذج ما لم تفعّل التقارير وتملأ القيم؛ قد يترتب على المزود الخارجي رسم حسب حسابك. يرسل التطبيق مقاييس نتائج مختصرة لا مفاتيح Telegram أو نصوص المحادثة. تُحفظ التقارير وإصدار prompt/model في `data/ai_reviews/`.

## 7. الشارت ونتيجة التوصية

يُرسم الشارت من OHLCV نفسه الذي أنتج التوصية، ويُحفظ PNG ونسخة البيانات المصدرية تحت `data/charts/` قبل الإرسال. يفشل نشر التوصية إذا تعذر إنشاء الصورة أو حفظ بياناتها. تعرض الرسالة هدفاً نهائياً واحداً يطابق الصورة.

المصدر الحالي لا يوفّر Bid/Ask؛ السبريد والانزلاق غير محسوبين. إذا لمست الشمعة نفسها الوقف والهدف، تُسجل النتيجة `AMBIGUOUS` بلا سعر خروج أو نقاط أو R، بدلاً من تخمين ترتيب اللمس. قد تبقى النتيجة تقديرية لأنها مبنية على OHLCV وليست سجلاً بتنفيذ وسيط.

## 8. الاختبار، السجلات، والاستعادة

شغّل الاختبارات محلياً قبل أي نشر:

```bash
.venv/bin/python -m pytest -q
.venv/bin/python -m compileall -q .
.venv/bin/pylint --errors-only config.py main.py backtester.py strategy_evolver.py src tests
```

توجد سجلات الأوامر الإدارية في `data/admin_audit.jsonl`، وحالة مراقبة الصحة في `data/health_state.json`، وسجل التوصيات في `data/signal_lifecycle.sqlite3`. لا ترسل هذه الملفات إلى قنوات عامة؛ قد تحتوي تفاصيل تشغيلية ونتائج تاريخية.

للرجوع إلى نسخة ما قبل إصلاحات 2026-11-07 (الأوامر ونتائج الصفقات وفحوص النشر):

```bash
git fetch --tags
git checkout backup-before-fixes-2026-11-07
```

أو من GitHub: افتح المستودع، واختر Tags ثم `backup-before-fixes-2026-11-07` وحمّل الملف المضغوط. قاعدة بيانات التوصيات متوافقة: الأعمدة الجديدة (`telegram_message_id` و`strategy_version`) تُضاف تلقائياً ولا تمنع النسخة القديمة من العمل.

للرجوع إلى نسخة ما قبل التعديلات الأقدم:

1. أوقف العملية وخذ نسخة من مجلد البيانات الحالي.
2. فك ضغط ملف `Forex_backup_prechange.tar.gz` إلى مجلد منفصل، ولا تكتب فوق الملفات الحالية قبل مراجعة النسخة.
3. استعد مجلد البيانات الدائم من نسختك الاحتياطية الخاصة إن كانت لديك؛ الأرشيف السابق يحتوي المشروع كما كان وقت إنشاء النسخة ولا يتضمن بيانات تشغيل جديدة أُنشئت لاحقاً.
4. أعد إعداد `.env` يدوياً من `.env.example`؛ لا تستعد أسراراً أو مفاتيح من سجلات عامة.

**ملاحظة:** الاختبارات الآلية لا تثبت الربحية ولا تكفي لإعلان جاهزية إنتاجية. يجب اختبار صلاحية Telegram، النشر الفعلي للصورة في القناة، وصول Webhook من TradingView، ومصدر الأسعار/الأخبار من بيئة خادمك قبل الاعتماد عليه.
